# Opus 지적에 대한 Astra 반영 기록

이 문서는 모델 리뷰를 인수 판단에 쓰기 위한 변경 기록이다. 사용자 의도 승인이나 출시 승인을 대신하지 않는다.

## 첫 리뷰

Opus는 자격증명과 결과 데이터의 구분, 사람의 신뢰 기준, 향후 호환 실행의 격리 조건을 지적했다. 모두 제안 계약에 반영했다. 출력 스키마, 승인 피싱, request ID 재사용, 로그인 복구, 불변 감사·백업, IAM 우회, 관리 API 인증, 단건 값 보기, 승인 폭주도 보강했다.

## 두 번째 리뷰

판정은 의도 정렬 한정 조건부 PASS였다. 후속 지적은 다음과 같이 처리했다.

- 통제면 자격증명: Opus 지적에 따라 ZeroPW 자기 인프라와 복구·하네스 관리 자격을 workload 연결 대상에서 제외했다. 제품의 다른 프로젝트 API 키 관리 기능은 유지하며 ZeroPW 경계를 변경할 권한이 없는 키만 허용하고 사용량 정책을 요구한다.
- 결과 범위: 첫 저장소 검증 결과를 reachable·is_private·archived 불리언, DB 결과를 연결 enum으로 명시했다. 자유 텍스트를 몰래 메타데이터로 분류하지 않는다. 풍부한 결과가 필요한 경우 별도 정책 설계를 요구한다.
- 사전 허용: 어댑터 digest·연결·비밀 버전과 입력 범위까지 묶고 변경 시 무효화한다.
- 리뷰 gate: Opus Critical/High를 Astra가 낮춰 종결하지 못하고 원문·증거를 보존한다.
- 반복 승인: 같은 digest·연결·버전·대상·정책 범위에만 해당한다. 어댑터 등록이나 권한 확대를 포괄 승인으로 재사용하지 않는다.
- 전체 정지와 이상 사용 알림을 추가하고 감사·승인 장애 시 신규 실행 거부를 인수 기준으로 정했다.
- 출처: 별도 source-check.md에 이미 확인 기록이 있었다. 이전 리뷰 입력에 포함하지 않아 Opus가 보지 못했다. 이제 함께 제공한다. 조회 도구는 HTTP 상태를 반환하지 않았으므로 임의 200을 기록하지 않았다. 공식 문서 확인과 도구 없는 Opus 설계 리뷰는 별도 증거다.

## 남은 제품 정렬

사용자는 개인용 CLI·API 범위와 제품·하네스 모두 클라우드인 점을 확인했다. 등록된 작업 중심 실행의 자유도와 첫 실제 CLI·필요 결과는 아직 확인 전이다. 제공자·예산·리전과 구체적인 통합은 구현 전에 확정한다. 문서는 이 부분을 사용자 확정 결정으로 기록하지 않는다.
