Claude Opus의 최종 판정은 의도 정렬 한정 PASS다. 문서가 서로 일관된 제안으로 정리되어 사용자에게 제시할 수 있다는 뜻이다. 사용자의 제품 승인, 구현의 안전성, 배포 승인이나 보안 인증을 뜻하지 않는다.

## 검토와 수정

첫 검토는 REVISE였다. 키 비노출과 결과 데이터 공개의 차이, 모델 밖에서 이루어지는 사람의 승인, 임의 CLI 실행과의 충돌을 지적했다. 승인 화면 위조, 재시도·회수, 로그인 복구, 로그·백업과 클라우드 권한 우회도 보강했다.

두 번째 검토는 조건부 PASS였다. ZeroPW 자신의 관리 자격을 작업용 연결에서 제외하고, 첫 작업의 결과 필드를 명시했다. 어댑터·키 버전이 바뀌면 사전 허용을 무효화하고 전체 실행 정지와 이상 호출 알림을 추가했다.

세 번째 검토는 위 수정에 대한 제한된 재검증이었다. 새 Critical·High·Medium 모순을 발견하지 않았으며 의도 정렬 한정 PASS를 반환했다. 남은 Low는 출처 확인의 증거 성격, 제외 목록의 결제·하네스 호출 키 표기, 위험 수용과 해결 상태의 구분이었다. 최종 검증 이후 이 세 항목의 문구를 정리했다. 문구 정리 후 추가 Opus 검토는 수행하지 않았다.

## 현재 사용자와 맞출 부분

개인용 CLI·API 중심 범위와 제품·개발 하네스 모두 클라우드라는 점은 확인됐다. 다음은 아직 제안이다.

- 임의 명령에 비밀을 주입하는 대신 등록된 작업을 실행하는 방식이 원하는 자유도에 맞는지.
- 첫 실제 CLI 작업과 필요한 결과가 무엇인지. 상태 확인은 검증 예시이며 풍부한 업무 결과에는 별도 데이터 노출 정책이 필요하다.
- ZeroPW 자신의 관리·복구·하네스 자격은 별도 운영 체계에 둔다는 경계.

클라우드 제공자·리전·예산은 구현 전에 정한다. 현재 클라우드 인프라와 제품은 배포하지 않았다. 보안 공격 시나리오는 인수 기준이며 아직 실행한 테스트 결과가 아니다.

## 실행 증거

제품 기획과 문서는 Astra가 작성했고, gpt-5.6-sol 서브에이전트 두 개가 공식 기능 조사와 작업 폴더 점검을 수행했다. 검토 응답의 주모델은 claude-opus-5로 기록됐다. CLI의 사용량 metadata에는 claude-haiku-4-5 보조 호출도 함께 기록되어 있으며 용도는 명시되지 않았다. 이를 별도의 Sol 검토나 Opus 단독 호출로 표기하지 않는다.

리뷰 원문, JSON 응답과 입력 문서 digest는 프로젝트 docs/reviews에 보존했다. 문서는 현재 로컬 작업 폴더에서 작성했고 Opus 검토는 로컬 Claude CLI를 통해 호출했다. 이 실행이 목표 클라우드 개발 하네스의 구축을 의미하지 않는다.
