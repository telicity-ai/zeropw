## Deliberately limited claims, not findings

1. **Invalid original Commit/Fact signatures can reach IntegrityCheckedPayload.** The strongest security concern is that a signed outer manifest must never replace original record authority. Here this behavior is explicitly required by original decision lines 857–863 and revised task lines 227–234: semantic verification must be a separate gate, not a misleading partial signature verifier. `team_checkpoint_payload.rs:180–237` includes the coherently re-attested invalid-inner-signature candidate. The current inert result and lack of runtime caller preserve that distinction. Treat it as a blocker only if future code admits or installs such a result without the later checks.
2. **A caller can supply fabricated local expectations or a chosen wall time.** This is not a constructor for human approval or session authority. Revised task lines 57–60 deliberately allow that metadata factory; actual persisted two-sided approval, current revocation/session checks and monotonic deadlines are M2-G06/G07 obligations. The inspected implementation enforces equality against the supplied full pin/context and wall value; it does not claim those external facts were established.
3. **Final overlay, authority replay, wrap usability and durable publication are absent.** The strongest counterargument would be a consumer mistaking the result for a usable checkpoint. The module documentation, type names, fixed candidate stage, lack of installer/runtime calls and preserved G01–G10 disclaimers address the current bounded slice. The original decision lines 885–896 and revised task lines 65–71 keep all full-M2 gates open. This collection does not turn any of them into a pass or a new M2a defect.

No in-scope fix is requested on this static evidence. For integration, preserve the private/inert API and explicit unsupported snapshot status; do not reinterpret IntegrityCheckedPayload or serialized candidate provenance as semantic admission or installation authority. A separate semantic/durable implementation must satisfy the existing G01–G10 contract and receive its own final-head review and validation.
