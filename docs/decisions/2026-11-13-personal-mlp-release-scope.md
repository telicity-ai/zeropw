# 개인용 MLP 최소 출시 범위 — 2026-11-13

이 문서는 사용자의 최신 명시 지시를 기록한 coordinator 범위 갱신이다. 새로운 Astra 수용, Opus PASS 또는 배포 증거가 아니다.

사용자 지시:
> 심각하지 않은 버그에 대해서는 현재 모두 고칠 필요는 없고 personal로 작동하고 사용자가치를 제공할 수 있기만 하면 돼. 너무 복잡하게 하지 말고 최소 기능들만 작동한다면 MLP 라고 생각하고 deploy 하자.

## 이번 배포에서 제공할 가치

한 사람이 두 Mac에서 로컬 Personal Vault를 사용한다. 양쪽 기기가 온라인이면 승인된 두 기기 사이에 최초 암호화 금고와 이후 변경 버전을 동기화한다. 로그인 정보·비밀번호·API 키 저장·사용, 충돌 표시, 삭제 후 사용 차단을 확인한다. 기존 HTTP gateway와 SSH signer의 비밀 격리는 유지한다. 서버 이용 초대와 금고 접근 승인을 분리한다.

## 출시 차단과 후속 작업

- 비밀 노출, 조용한 데이터 유실, 인증·권한 회수 우회, 핵심 설치·동기화가 동작하지 않는 결함은 먼저 해결한다. 현재 ZPPVBOOT-OPUS-01 HIGH와 macOS 핵심 실행 실패를 우선한다.
- 큰 금고의 성능 최적화, 일반 M2 복구·교체·추가 기기, 대규모 수용 인원, 기업망 443 전용 지원, UI polish와 낮은 심각도의 버그를 모두 해결하는 것은 첫 배포 조건이 아니다.
- ZPPVBOOT-OPUS-02 MEDIUM은 개인용 기본 사용을 막는 측정 결과나 별도의 안전 영향이 없다면 후속 성능 작업으로 남길 수 있다. 인증·무결성 검사를 삭제하거나 예산을 임의로 늘려 우회하지 않는다.
- ZPPVBOOT-OPUS-03 LOW의 이미 작성한 국소 수정은 보존하고 합친 변경의 관련 회귀를 확인한다. 이 지적 하나를 위해 별도 설계·전수 리뷰 주기를 추가하지 않는다.
- 심각도와 원래 리뷰는 그대로 보존한다. 미수정·수용 위험·검증 실패·미실행을 구분하며 미수정을 해결로 표시하지 않는다. 현재 HIGH 지적을 비심각 버그로 자동 재분류하지 않는다.

## 검증과 배포

기존 rust/verify.sh와 CI는 약화하지 않는다. 소스가 확정되면 격리된 Linux/macOS에서 관련 회귀와 기존 verifier를 실행하고, macOS의 실제 설치·페어링·최초 동기화·변경·충돌·삭제·재시작 경로를 우선 확인한다. 기존 실패가 테스트 준비 문제인지 제품 결함인지 근거로 구분한다. 매 변경마다 큰 추가 matrix를 반복하거나 무관한 과거 이슈를 모두 닫는 것을 요구하지 않는다.

실제 물리적 두 Mac이 없으면 VM 결과와 미검증 사실을 구분한다. 새 Opus 검토는 바뀐 보안·기능 경로와 남은 심각한 결함에 한정하고, 낮은 심각도의 지적이 남았다는 이유만으로 수정 루프를 반복하지 않는다. Astra 수용과 사용자 위험 승인은 해결·PASS와 별도 기록한다.

Oracle 무료 자원에 개인용 beta 서비스와 coturn을 배포한다는 기존 사용자 승인은 유효하다. 새로운 유료 자원은 만들지 않는다. 설치 artifact·필수 네트워크·TLS·health·재시작·rollback·등록 DB 복구의 실제 상태를 확인한다. 용량은 측정 전 보장하지 않는다. 일시적인 원격 서비스 중단은 원래 제품 범위에서 허용되며 로컬 금고 사용은 유지한다.

작업자·운영 자격증명 분리, 미해결 custody·취소·lease의 권한 제한은 계속 지킨다. 해당 과거 리소스를 조회·입양·종료하거나 증거·실패를 지우지 않는다. 이 범위 변경은 운영 권한 확대나 미검토 코드 실행 승인이 아니다.
