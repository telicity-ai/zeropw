# M2b: semantic admission boundary and remaining M2 slices

2026-11-07. Actual design model: **gpt-6-astra**, **ultra** reasoning, T3 Code through the Codex harness. No further model revision or sampling settings were exposed. This is a design and implementation handoff, not implementation, Opus review, executed validation or release acceptance. No subagents or workflows were used.

## 1. Decision and authority

Implement **M2b.1: retained authority and non-removal fact analysis**, as the finite next Sol task in [implementation-task.md](implementation-task.md). It must verify original signatures, genesis, full device equality, ordered authority transitions, author heads, historical role evidence and the complete original M1 tombstone set. It returns a private-construction, noninstallable candidate. It must reject `member_removed` fact inputs explicitly in this first semantic slice; it must not ignore them or claim to have verified removal-dependent authority. Commit-only removals are included. The following slice adds fact-removal admission/scheduling and the exact final overlay. This division avoids making an unfinished removal-admission algorithm an authority source.

All full-M2 gates remain open after M2b.1. A candidate is useful to the next verifier stage; it is not a runtime feature. No public `VerifiedCheckpoint`, receipt, fact-install conversion, ACK or READY is authorized by this task.

Accepted constraints, unchanged:

- macOS-first MLP; personal encrypted version synchronization and actual eventual implementation/Oracle deployment; separate service invitations and vault membership approval; direct transport with coturn fallback.
- No server vault, plaintext or offline vault copy, operator decryption, or service-operator peer-add bypass. HTTP authentication stays in the trusted gateway; SSH signing remains a core separate trusted path.
- The joining human approves the **particular complete inviter device record** as checkpoint administrator. That administrator separately approves the recipient identity and role. Service membership, invitation possession and TLS/team authentication are not these approvals.
- The administrator attests completeness of the omitted prefix and admitted fact set. Surviving signatures cannot establish absence of omitted events. Provenance is always `administrator_attested`, never full-history verification.
- Fresh environment only; no silent replacement, version overwrite, fact loss or tombstone resurrection. Existing state repair and arbitrary snapshot merge remain outside M2.

New decisions in this document concern semantic proof stages, conservative eligibility, the next implementation boundary and an explicit renewal-format requirement. They do not change old commit/fact/snapshot meaning or M2a parsing. The four M2a documents and all original evidence remain unmodified.

## 4. Proof representation audit: v1 sufficiency and limits

No new proof is obtained by serializing a `Facts`, `FoldResult` or candidate. The proof bundle is the paired original manifest and payload, with immutable checked spans, original signed records, independently supplied local expectations and independently collected local deny/collision knowledge.

| Obligation | Existing bytes / decision |
| --- | --- |
| Genesis and identities | `devices`, named genesis whole commit, original `env.init.owner_device`; enough if present and consistent. No record can be synthesized from snapshot membership. |
| Membership/ownership/generations | Whole `env.init/member.add/member.set_role/member.remove/owner.transfer/dek.rotate` commits in `commits.records`; exact set in `authority_commit_hashes`. Enough for retained replay; completeness is administrator-attested. |
| Heads and removal witnesses | Whole commits plus `heads` and `removals.witness_commit_hashes`; enough for signed references and schedule comparison. Missing original bytes are not repaired by adding a hash. An earlier witness outside the exported covered vector requires a new full cut including it, not an out-of-vector exception. |
| Original facts | Every `Fact` including sig, exact admitted/tombstone sets; enough for signatures, target checks, effects and the explicit administrator-attested historical basis below. **No original admission time, admission vector, causal clock, arrival order or remote receipt** is present. Do not claim to independently reconstruct those. |
| Omitted data prefix | Snapshot document and version order are attested bytes. There is no per-field source-operation provenance or original omitted commit. This is the accepted trust boundary, not independent full-history proof. Where a particular comparison requires an original operation, it must be supplied as a whole existing commit or eligibility fails. |
| Final overlay | Full unflushed document, complete facts, schedule and expected digest are present. Enough to recompute the final overlay of that attested base, **not** to prove the base equals all deleted history. Digest equality must be computed, never assumed from the signature. |
| Wraps | Original whole source commit/op index plus exact selected wrap, generation and unavailable list. Enough for public source/role checks. AEAD validity/DEK length and synthetic ciphertext usability require later trusted key-bearing work. |
| Known local restrictions/collisions | Absent from the remote format by design. Obtain separately under local synchronization; never derive an empty local state from the manifest. |
| Approval, live session, READY, durable receipt | IDs/nonces and metadata bind the intended entities; they do not contain proof of local human action, session liveness or durability. Later private local capabilities and separate READY supply those stages. |
| Renewal after original invite expiry | **Impossible in M2a v1:** `expires <= authorization_expires <= approval.invitation_expires_at_ms`. A fresh nonce does not change this bound. See §11 for an explicit versioned amendment; v1 remains initial-authorization-only. |

The v1 schema can carry additional **original whole commits** for comparisons without adding fields; it cannot manufacture missing originals. Adopt these explicit fail-closed rules:

1. Missing genesis, authority operation, head, necessary removal witness or target-specific original proof: `team_bootstrap_history_proof_unavailable`. Do not invent a head HLC, sequence zero, receipt or matching digest.
2. A retained authority operation skipped by the real rules, including a rejected attempt to remove an owner, is not a successful transition. The initial checkpoint eligibility policy refuses that bundle as `team_bootstrap_authority_unproven`; it never deletes that operation from the evidence. Ordinary log/fold behavior continues to retain and skip it as before. This conservative restriction is explicitly narrower than all legacy histories.
3. Fact-removal cases whose historical admission cannot be demonstrated under §7's conservative rules remain unsupported even when signed by the pinned admin. A new unsigned claimed “admission timestamp” would not repair the missing proof. No additional historical receipt format is invented here.
4. Missing nonauthority data history is allowed **only for the accepted attested base**. It cannot excuse contradiction with a supplied original op or known local restriction, nor justify an independent-history label. Missing data needed to disambiguate a retained conflicting version/target comparison is a precise history-proof refusal.
5. A legacy source can obtain the exact originals from an authorized peer that still has them, then retry with a fresh cut/approval as applicable. If nobody retains them, explain that this environment cannot use this bootstrap route. Keep existing authorized devices usable subject to their known restrictions. An explicitly human-created new environment may re-store credentials through the trusted administration surface under new identities; it must not resurrect tombstoned IDs or export a server/offline plaintext copy. Do not promise migration of every old compacted environment.

No parser clause is superseded. No `raw_value`, Cargo/feature change, canonical-helper rewrite, fixture regeneration, unsigned proof metadata, opaque extension field or silent v1 drift is permitted.

## 5. Owned inputs, private stages and errors

M2b.1 exposes a pure analysis entry, not an import entry:

```rust
// Proposed APIs, not existing source.
pub struct SemanticLocalInputs { /* owned observations, private fields */ }
pub struct RetainedAuthorityCandidate<'m, 'p, 'b> {
    /* private references to manifest/payload/local inputs and private analysis */
}
pub fn verify_retained_authority<'m, 'p, 'b>(
    manifest: &'m ManifestAttestation,
    payload: &'p IntegrityCheckedPayload<'b>,
    local: &'m SemanticLocalInputs,
) -> Result<RetainedAuthorityCandidate<'m, 'p, 'b>, SemanticError>;
```

`SemanticLocalInputs::from_local_observation` owns: complete local recipient `DeviceRecord`; expected environment, approval hash, session/onboarding nonces; intended local project/environment mapping; observation revision identifier; typed inventory of existing commits/facts/checkpoints/derived team entries/unsent edits/pending imports/completed imports; occupied local secret and connection IDs with their scopes/ownership; known original admitted fact objects and hashes; local deleted-ID/binding restrictions and required-tombstone-support state. These are **caller observations**, like M2a expectations, not authenticated approval proofs. Constructor validates shape and cross-references; there is no `approved: bool`, remote deserializer or default “empty means trusted” constructor. Tests explicitly build synthetic observations. Runtime construction is forbidden until the later trusted collector exists.

The result owns bounded analysis metadata, original fact objects indexed by hash, exact head evidence and qualifying role-interval references. It borrows the immutable exact bundle and local observation; it cannot outlive them. All fields/constructors are private; no `Deserialize`, `From<Value>`, unchecked setter, `Default`, generic validator callback, raw `Facts` export, disk path or install conversion. Public accessors expose only redacted stage/coverage summaries and hashes/counts. The stage is `retained_authority_checked_not_admitted`, not a replacement value in M2a candidate JSON. No production caller is added.

Extend payload internals to retain the already validated `PayloadIndex` metadata and disjoint record spans, including ancestor depth. Private sibling access only; no public span constructor. Materialize one original record at a time for signature/schema checks, retaining compact order/key/index metadata; do not serialize into legacy `Value::deserialize` or rescan the whole payload per record. Authority ops are referenced by whole-record hash and original op index. Original fact objects must remain available for eventual M1 storage. Snapshot authority projection may be inspected without retaining duplicate full snapshot trees.

Later stages are distinct: `SemanticCheckpointCandidate` (including removal admission and computed final fold), `GenerationCheckedCandidate`, live-session `ReadyProof`, then an importer-private prepared transaction and finally `CommittedImport`. Only the visibility transaction can construct committed provenance or expose receipt/ACK eligibility. No stage can be reconstructed from inspection JSON. Runtime revocation/deadline checks may invalidate any earlier candidate.

Use separate closed `SemanticError` reasons, preserving M2a errors unchanged: `team_bootstrap_authority_unproven`, `team_bootstrap_history_proof_unavailable`, `team_bootstrap_fact_contradicted`, `team_bootstrap_semantic_mismatch`, `team_bootstrap_existing_state_unsupported`, `team_bootstrap_generation_unavailable`, `team_bootstrap_semantic_scope_unsupported`, and the existing binding/signature/schema reasons through a redacted wrapper. No raw record, key name, ciphertext, signature, path, numeric token or peer error is printed. A bounded component/record/op index is acceptable. Error precedence is not an acceptance condition.

## 6. Exact retained-record and authority algorithm

These checks are mandatory; M2b.1 implements them with no `member_removed` facts. §7 extends the same algorithm with authenticated removal placement in M2b.2.

1. Require the private manifest hash in the integrity payload to match the supplied attestation. Recompare all supplied local bindings and complete local recipient record. M2a has already bound the complete pinned signer/session peer record. Inputs from another manifest, approval, recipient agreement key, environment, attempt or session fail.
2. Check every device table entry and every embedded `owner_device`, `member.add.device` and snapshot `members[*].device`. Require valid self-signature, computed fingerprint, and equality of **sign_pub, agree_pub, sig**, plus canonical dictionary equality to the table copy. Refuse noncanonical/coercive embedded copies for checkpoint eligibility without changing ordinary legacy parsing. All referenced identities, including vector-zero/seen/wrap targets and removed members, must resolve; unknown devices are never granted membership by this table.
3. For every whole retained commit: original environment and canonical equality/hash, `verify_commit`, every operation's existing schema. For every fact: original environment and canonical equality/hash, M1 `validate_fact_target` and `verify_fact`. Do not apply any effect before this pass completes. Corrupt inner signatures must fail even after an attacker recomputes every outer digest and validly re-signs the manifest.
4. Find exactly one `env.init` operation, at op 0 of the named genesis commit, authored at sequence 1 by `env_owner_fingerprint(env_id)`. Its original owner record equals the verified table. The original genesis signature must verify under that record. No snapshot owner or pinned nonowner admin can replace it. Reject another `env.init`, even in a differently named record.
5. Compute the authority-commit set from actual op names (the six kinds above); require exact equality to the declared sorted set, not subset membership. Named recipient admission must contain exactly one successful `member.add` of this full recipient record with the approved role. For this fresh identity, reject multiple attempted admissions or a different admitted role, including later promotion/demotion that no longer matches the approval.
6. Index by `(author, author_seq)` with exact `PyInt`. Retained sequences must be positive, unique and at/below vector. Along increasing sequence, HLC pairs must increase strictly, including across retained gaps. Each `seen` entry must be nonnegative and at/below the covered vector; self-seen cannot reach this or a future sequence. If the referenced commit is retained, its numeric HLC cannot be later than the observing commit. No requirement is invented that omitted sequences equal zero or that every `seen` reference be retained. These are conservative checkpoint consistency checks, not changes to legacy receive.
7. Each positive vector entry has its exact signed last admitted commit, hash and numeric HLC; a zero entry has no head. A head is not permission for its author to remain active. Keep the original HLC string for signature/hash; compare only parsed numeric pairs. The full cut boundary is the maximum existing total-order key among these heads/retained records, not an arbitrary manifest timestamp.
8. Replay authority in `commit::sort_total_order` order, with original intra-commit op order. Start from `new_document(env_id)`, not supplied members. Use existing pure member/owner/DEK handlers and the shared removal scheduler. Process all authority operations even in mixed data/authority commits; never extract and re-sign an operation. Keep outcomes for each op.
9. Nonauthority op schemas and role prerequisites are checked at their original position; all current data/settings handlers require active admin. They do not alter membership/owner/DEK state. Do not pretend to replay their data effects on an empty document. A stale or unauthorized retained op is an eligibility refusal; a missing data target/outcome is left to the data stage, not treated as success. No handler skip can grant authority to a following op.
10. Any skipped authority operation refuses this checkpoint (§4). Owner transfer must be by the then-active owner, to an active member; it promotes the successor to admin but does not silently demote the former owner. Owner role changes/removal fail under the existing rules. Removed identities cannot be re-added. An owner's rejected self-removal remains rejected evidence, not a successful transfer/removal or reason to suppress later history.
11. Compare the replayed unflushed `owner`, complete `members` (name/role/status/full records) and complete `dek` state canonically with the snapshot's projection at the full cut. Compare the post-removal final projection separately in M2b.2. Require active admin signer (`is_admin`, not role text alone) and active recipient with the exact approved role at the cut/final state. Bind the successful named admission and all selected wrap source operations to the replay trace. A device self-signature is not a role grant.

Extract a small pure `fold::checkpoint_authority_trace` seam using existing handlers, with explicit authority projection and original op positions. It must have no filesystem, audit, KMS or signer input. It may return observations/skip records; it must not offer a switch that suppresses authority checks. Ordinary fold continues to use its original policy and output bytes. Regression tests must compare the projection against ordinary complete-history `fold` over independent signed examples. Do not refactor `load_facts` into accepting a Boolean “attested” parameter.

## 7. Fact admission, contradictions and removal proof

### Non-removal facts (next task)

After original signature/schema/identity checks and authority replay, enumerate actual active-role intervals from successful authority operations, including intra-commit changes. Keep signed endpoints as `(commit_hash, op_index, before/after)`, not fabricated fact-admission timestamps. `connection_disabled`, `secret_version_revoked` and `secret_deleted` need at least one active-admin interval; `incident` needs an active-member interval. Current role alone is insufficient for historical irreversible facts. Unknown, never-admitted and never-qualifying authors fail even with a valid pinned manifest signature.

For every accepted-in-analysis fact, record **`administrator_attested_historical`** with exact fact hash, manifest hash, payload hash, approved signer record/hash, approval hash and qualifying interval. The administrator's exact admitted set attests that this original fact was admitted while an applicable basis existed. Do not claim its HLC proves admission at that time. A later demotion/removal alone does not invalidate an already admitted irreversible fact. Conversely, no eligible interval, a failed grant, conflicting device record, wrong environment, unknown target shape or retained removal evidence eliminating the claimed authority is a contradiction; refuse the complete bundle, do not drop the inconvenient fact.

This is a **new checkpoint-only basis** allowed by the accepted trust model, including historical `secret_deleted`. It does not extend M1's receipt-free loader fallback, authorize a new live fact from a removed admin, or certify what an omitted admission event contained. In M2b.1 the facts are analyzed but not locally admitted. Use M1's exact `apply_fact` effects after checking every fact; preserve every original object and hash. Compare `tombstone_gate::digest(&facts.tombstone_facts)` with both the M2a set and signed digest. Two distinct valid deletions of the same ID remain two hashes. Deletion of an ID with no versions is still retained. Never derive the set from `document.deleted`, secret count, vector or `snapshot_record.facts`.

### Removal-dependent admission (M2b.2, not the next task)

Removal facts affect the very authority being proved. Freeze the following conservative algorithm and unsupported boundary; do not feed an unauthenticated `Facts.removed_members` to a fold and call the resulting roles proven.

1. Verify all original records first. Build a **provisional** schedule from the complete signed candidate removal set solely to evaluate consistency; no output authority exists yet. Refactor/reuse `RemovalSchedule::new` with an observable placement trace. Recompute the exact claims, never trust transferred bounds.
2. A removal by another device is positioned at the earliest other-author fact HLC for the target. For each such fact, its witness is the lowest-author-sequence whole commit by **that fact's author** containing `dek.rotate.removal_fact_hash == fact.hash`. Its `seen[target]`, absent meaning zero under the existing rule, contributes a bound; the minimum bounds win. Another admin's rotation is not its witness. For initial full-M2 eligibility require that original witness for each other-author removal; a source still awaiting its rotation is not yet exportable through this route. This is stricter than ordinary M1's fact-HLC-only fallback and does not change it. Preserve all distinct original facts, even when their effects coincide.
3. Self-only removal is positioned by the lowest sequence whole commit by that target containing its own `member.remove`; that sequence is the bound. Self-fact HLC never advances/retards it. With neither applicable placement, M1 treats a bare self-removal as removed from the start. Do not guess a placement from the latest head. Such a checkpoint cannot establish prior authority from a fabricated position; return history-proof/authority refusal if the required original basis is absent.
4. `witness_commit_hashes` is exactly the unique union of the selected rotation/self-placement commits used above. Require every selected original and compare `bounds`, numeric-tuple-sorted `pending` and `self_placed` against the shared scheduler. Also check all retained possible witnesses; a later selected rotation cannot conceal an earlier retained one. Completeness beyond retained originals remains attested.
5. Evaluate other-author removal eligibility in the scheduled authority view **immediately before that removal cut**: author active admin, target admitted and not owner. Evaluate a self-removal immediately before its original placing op: target is that author, admitted and not owner. A skipped placing/authority op never becomes a grant. The ordinary scheduler may still use a skipped self-removal as a bound; preserve that fact in diagnostics and refuse this checkpoint, rather than changing the legacy rule.
6. Reuse M1's precisely scoped reciprocal-removal rule only when the original author-to-target relation proves that the author was removed solely by this same target. Preserve commit removals and every unrelated removal when obtaining that view. Do not clear all removals, rely on `relaxed_document`, or grant every historical admin power to remove unrelated members. If that exact view cannot establish a basis, refuse; there is no attestation override for a retained contradictory removal.
7. Run the final authority replay with **all** now-eligible removals, their bounds and pending placements. Commits past a bound cannot contribute ops even if backdated. Pending cuts apply before commits at equal HLC. `owner.transfer` to any fact-removed target is skipped wherever it sorts, matching M1. Reject any resulting skipped authority operation or mismatching snapshot authority; no iterative deletion of facts/commits to make the result pass.
8. Recheck non-removal historical role intervals against this scheduled replay. An interval eliminated by retained removal proof cannot be recovered by suppressing removals. Later demotion/removal still does not revoke an interval that actually existed. Compare final scheduled authority to the snapshot and keep the complete original set.

This admits independently demonstrable removal histories and refuses ambiguous ones. In particular, v1 lacks original fact admission/knowledge chronology: a legitimate earlier admission followed by a retroactively positioned removal may fail this conservative test. That is an explicit unsupported history, not proof of maliciousness and not a reason to change ordinary M1 behavior. Supplying the original missing signed witnesses/history may resolve it; a sender-local receipt, guessed event ordering or newly invented digest cannot. Supporting additional such histories needs a separate additive evidence contract backed by real retained originals, not a permissive flag. Full M2 cannot be accepted while its required normal removal/transfer cases fail this algorithm in tests; return any such concrete contradiction to Astra, preserving the independent M2b.1 work.

## 8. Final document, version order and generations

M2b.1 intentionally does **not** validate `expected_final_document_sha256`. An authority candidate must still be obtainable from a structurally valid, false final-digest M2a input; it must have no API suggesting that digest is verified. M2b.2 must turn that case into failure before producing its stronger candidate.

M2b.2 first validates the document's known containers/fields used by fold and derivation, while preserving opaque legacy values. Refuse a conflicting embedded `_version_order`; the ordinary fold permits it to override the separate order, so blindly passing the snapshot to `fold` is unsafe. For checkpoint eligibility, `_version_order` must be absent; leave the old loader unchanged. Check exact IDs, secret kinds, version objects/statuses, generation references, active pointers and connection policy shapes using existing helpers.
